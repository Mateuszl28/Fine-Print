Fine PrintApp map · a snapshot of the code

Where everything lives

Fine Print reads a contract (pasted text, a photo or a PDF), marks risky clauses on the contract text in red, yellow and green, adds up what it really costs, and writes a letter. It's one Next.js app with two halves: the page in your browser and one server route that asks a language model (Gemini 2.5 Flash through Vercel AI Gateway) and then checks the model's work in code. Nothing is stored.

Reference route (3 stops)

Not toured live — open these to follow the same action yourself

  1. app/api/analyze/route.ts → analyze()
    Builds the request (text, or the photo/PDF as file parts), asks the model for an object matching analysisSchema with generateText + Output.object, then hands the result to buildReport. Search for const MODEL to see which model runs.
  2. lib/checkReport.ts → locateQuotes() and totalCost()
    The trust layer. fold() normalises spacing, quotes and case so each quoted clause can be found in the real contract text; anything not found is dropped and counted in droppedQuotes. The true cost is summed here in cents, never by the model. Tests: lib/checkReport.test.ts (npm test).
  3. components/HighlightedDoc.tsx → HighlightedDoc
    Splits the contract text at each clause's start/end and wraps those ranges in <mark class="hl hl-red">. The highlighter look itself is the .hl rule in app/globals.css.

A practice to reuse

Let the model write; let code check. The spec decided early (spec.md > Report checker) that every quote must be found verbatim in the contract and that the total is added up in code. That made the model's output measurable: each test run printed located, dropped and whether the total matched the itemised lines. When the first real runs counted a refundable deposit and a financed fee twice, the breakdown made it visible and the prompt was fixed (checklist.md > Revisions).

On another project: whenever an AI produces facts you'll show to people (quotes, numbers, dates), decide up front what can be verified deterministically, write that check and a test for it, and print a pass rate on real examples before trusting the output.
